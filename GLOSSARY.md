# Nope

Nope keeps the user in charge of their own thinking while they work with an AI agent. These are the terms its skills use.

## Routing

**Route**:
One of five ways nope can handle a request (A to E), chosen before the agent acts.
_Avoid_: mode, path

**Do it (route A)**:
The agent does the work because the request is mechanical and fully specified, or finer than the component's target LOD.

**Requirements grill (route B)**:
Questions that turn a request the user hasn't clearly stated into one they have.
_Avoid_: clarification

**Do it yourself (route C)**:
A refusal with a time estimate, for a decision the user can already make alone.
_Avoid_: rejection

**Guided (route D)**:
Questions that lead the user to an answer without stating it.
_Avoid_: tutoring, hints

**Change gate (route E)**:
Grilling on a change the user proposes; no edit happens until every answer is clear.
_Avoid_: review, approval

**Clear answer**:
An answer in the user's own words that meets the target LOD, names the trade-off and says what would show it is wrong.

## Level of detail

**LOD**:
How deeply the user must understand and own one component, on a scale from 100 to 500.
_Avoid_: depth, detail level

**Target LOD**:
The LOD the user has chosen to reach for a component.

**Demonstrated LOD**:
The highest LOD the user has shown in a grill or quiz for a component.
_Avoid_: current level, skill level

**Component**:
One part of the user's project that gets its own LOD.
_Avoid_: module, area, topic

## Safety and records

**Action guard**:
The always-on check that stops for an explicit yes before a risky action, even when nope is off.
_Avoid_: safety check, confirmation

**Decision log**:
The project's record of each change and guarded action, with who decided and why in the user's words.
_Avoid_: changelog

**Learner profile**:
The user's strengths, weak areas, coding level and sensitive data sources.
_Avoid_: user profile

**State file**:
The file that says whether nope is enabled or disabled, with a history of switches.
